# 미션 2-1 기록 (eslint 자동 수정)

## 전/후 숫자

| | errors | warnings | 내용 |
|---|---|---|---|
| 전 (스텁 브랜치 기준선) | 3 | 2 | `Btn.tsx`, `ComposeScreen.tsx`, `LoginScreen.tsx`의 prettier 오류 |
| 후 (`npx eslint .`) | 0 | 2 | 남은 것은 `@typescript-eslint/no-unused-vars` 2건 |

- 미션 문서(`tier2-quality.md` 2-1)는 9 errors / 2 warnings로 적었지만 스텁 브랜치 실측은 3 errors였다. 숫자가 다른 이유는 원본에서 같은 파일의 위치 타임아웃 블록이 prettier 대상이었는데 스텁 브랜치에서는 그 블록이 2-5 스텁이라 대상이 아니기 때문이다.
- `npx eslint . --fix` 결과는 포맷만 바뀐 커밋 `5e06fd2`(`style:`)로 분리했다. `npm run format`은 쓰지 않았다.

## 남은 warning 2건 처리 결정

- `src/screens/NotificationScreen.tsx`의 `permissionError`, `src/screens/ProfileScreen.tsx`의 `e` 모두 오늘 고치지 않고 미션 2-6·2-10으로 넘긴다.
- 이유: 변수를 지우거나 `_` 접두사로 조용히 넘기면 그 미션에서 할 일(에러 상태를 실제로 보여 주기)이 사라진다.

## 1-3과의 연결

- 위도·경도 아래 "권한 범위" 줄은 값 표시가 아니라 보조 안내다. 그래서 `LocationScreen.tsx`의 `styles`에 이미 있는 `styles.hint`를 골랐다(수정 커밋 `630f5cf`). 같은 화면의 `errorMessage` 줄이 이미 쓰던 스타일이라 새 hex는 늘지 않았다.
