# 미션 1-6 — logout 모듈 상태 리셋

## 변수 분류

`src/api/auth.ts` 모듈 변수가 로그아웃 때 어떻게 되어야 하는지 정리한 표.

| 변수 | 범위 | logout 동작 |
|---|---|---|
| `session` | 사용자 | `null` |
| `refreshInFlight` | 사용자 | `null` |
| `loginInFlight` | 사용자 | `null` |
| `refreshCount` | 사용자 범위 진단 카운터 | `0` (테스트 격리: 절대값 단정이 실행 순서와 무관해짐) |
| `generation` (신규) | 프로세스 | `+= 1`, 리셋하지 않음 |

`refreshCount` 답: 리셋한다. `NetworkScreen`은 갱신 전후 차이로 쓰므로 영향이 없고, 테스트에서 `getRefreshCount()` 절대값을 단정할 수 있게 된다.

## 선택한 해법: 세대(generation) 값

`logout()`이 `generation`을 1 올리고, `login()`·`refreshAccessToken()`은 시작할 때 `myGen`을 잡아 둔다. `await` 뒤에 `myGen !== generation`이면 throw 한다. `.finally`도 같은 세대일 때만 `loginInFlight`/`refreshInFlight`를 비운다 (옛 세대가 새 세대의 in-flight를 지우지 못하게).

- 경로 B (로그인 중 로그아웃): `login()` 비동기 블록의 `session = issueTokens()` 직전 검사로 차단.
- 경로 C (갱신 중 로그아웃): `refreshAccessToken()`의 `await` 뒤 검사로 차단. `fetchProtected`는 수정 없이 reject가 그대로 전파됨.

### 버린 대안: 완료 시점에 `session` 재확인

로그아웃 → 곧바로 재로그인하면 `session`이 다시 non-null이라 옛 작업이 통과해 새 세션을 덮어쓴다. 세대 값만이 "내가 시작한 세대인가"를 구분한다.

## 경로 D (재시작 시 user만 복원)

`App.tsx` 부팅 `useEffect`에서 `SecureStore` 값이 있어도 `isLoggedIn()`이 `false`면 값을 지우고 로그아웃 취급한다.

**바뀐 사용자 동작: 앱을 재시작하면 항상 로그인 화면이 다시 뜬다.** (토큰이 메모리에만 있어서.) `isReady` 전에 끝나므로 로그인 화면 깜빡임은 없다.

## 테스트

`tests/auth.test.ts`: 로그아웃 후 `isLoggedIn()` false / 경로 B / 옛 login `.finally` 격리 / 경로 C. `myGen !== generation` 검사를 주석 처리하면 경로 B·C 테스트 3개가 실패함을 확인한 뒤 복구했다.
