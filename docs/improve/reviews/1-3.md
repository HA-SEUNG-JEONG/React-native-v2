## 1. isReady가 없으면 부팅 때 무슨 화면이 보이나

부팅 때 잠깐 로그인 화면이 보일 수 있음

만약 이미 로그인이 되어 있는 경우라면 프로필 페이지에서는 로그아웃 버튼 및 탭 네비게이터에는 홈/프로필 탭이 보임

---

isReady의 역할은 AUTH_KEY에서 가져온 값을 SecureStore에 저장하는 역할을 담당한다. 이 값을 제대로 받아오지 못하는 경우도 발생할 수 있는데, 이 경우에는 인증 상태가 제대로 적용되어 있는지 알 방법이 없다. 그래서 isReady로 분기 처리를 하는 것이다.

---

isReady는 SecureStore 읽기가 끝났음을 알리는 플래그. 없으면 user === null 상태로 첫 렌더가 나가서, 로그인한 사용자에게도 로그인 화면이 잠깐 보인다.

- isReady는 저장하는게 아니라 boolean state
- isReady는 인증을 판정하는 용도로 쓰이는 게 아님

## 2. 왜 if (!user) redirect가 아니라 네비게이터 교체인가

로그인 직후 뒤로 가기를 누른다면 로그인이 됐는지 명확하게 알 수 없음

로그아웃을 하더라도 /home이 스택에 남아있다면 로그인/로그아웃을 반복적으로 실행했을 때 스택 관리가 어떻게 이루어지는지 헷갈릴 가능성이 있음

---

만일  redirect 방식을 쓴다면 스택 히스토리가 계속 쌓이게 된다. 이 과정에서 로그인 이후 뒤로 가기를 누른다면 redirect를 썼기 때문에 로그인 화면이 보이는 것이다.

보호 화면이 마운트 되고 redirect 되면 화면이 깜빡일 가능성이 있어 UX에 좋지 않다.

로그아웃 하면 RootStack.Navigator가 통째로 언마운트 되기 때문에 보호 화면으로 돌아갈 스택 자체가 없다.

## 3. login()과 signIn()은 각각 무엇을 어디에 저장하나

login -&gt; auth.ts 자체 메모리에 저장되기 때문에 앱을 종료하면 login 과정에서 생성된 토큰은 사라짐

signIn -&gt; SecureStore에 user 이름을 저장하기 때문에 앱을 종료해도 사라지지 않음, 재시작하면 user는 남지만 토큰은 사라지는 불일치가 발생한다.

## 4. signOut은 무엇을 하나?

모듈 상태를 리셋 -&gt; 쿼리 상태를 비움 -&gt; 유저 state를 리셋 -&gt; 기기 저장소에 있던 것들을 다 지움
