# 학습 누락 대비 계획

**작성일**: 2026-10-24 (토)
**연결 문서**: [study/rules.md](./study/rules.md) (밀렸을 때) · [study/README.md](./study/README.md) (날짜표) · [study/appendix.md](./study/appendix.md) (선행 관계)
**전제**: 하루 90분 상한. 빠진 시간을 채우려고 하루 시간을 늘리지 않는다.

---

## 1. 원칙

1. **빠진 날은 버퍼가 흡수한다.** 다음 날 분량에 얹지 않는다. 흡수처는 금요일 버퍼(10/30, 11/6, 11/13, 11/20, 11/27)와 예비일 11/26이다.
2. **흔적은 남긴다.** 시간이 없어도 시작 의식 5분과 기록 한 줄은 한다. 완료로 치지 않더라도 "기록 없음"으로 두지 않는다.
3. **미완 미션은 열린 상태로 둔다.** 반쯤 한 미션은 `reviews/N-N.md`에 "진행 중, 막힌 지점"을 적고, 다음 시작 의식에서 이어간다.
4. **선행 관계는 지킨다.** [study/appendix.md](./study/appendix.md) 선행 관계표 순서를 어기면 재현 결과가 틀린다.
5. **미검증은 미검증이다.** 📱 항목과 실기기 확인을 못 했으면 "미검증"으로 적는다. 복구하려고 "됐다"고 쓰지 않는다.

## 2. 상황별 대응

| 상황 | 판단 기준 | 조치 |
|------|-----------|------|
| 하루 빠짐 | 세션 0분 | 가장 가까운 버퍼 날로 그날 미션을 옮긴다. 버퍼가 이미 찼으면 예비일 11/26을 쓴다. |
| 60분만 가능 | 60분 세션 | 3절의 60분판 시간표를 쓴다. 미션은 줄이지 않고 읽기와 재현만 줄인다. |
| 30분 이하 | 짧은 세션 | 시작 의식 5분, "내일 할 일" 확인, 기록 한 줄, 다음 날 할 일 한 줄. 코딩하지 않는다. |
| 이틀 연속 빠짐 | 버퍼 1개로 흡수 불가 | 예비일 11/26까지 쓴다. 그래도 밀리면 4절 자르기 순서를 쓴다. |
| 힌트 3까지 갔는데 막힘 | [study/rules.md](./study/rules.md) 막힘 규칙 | 그날 멈춘다. 막힌 지점을 기록에 쓰고 다음 버퍼 날에 이어간다. 같은 미션에서 두 번 멈추면 목표를 "복원까지"로 낮춘다. |
| 시뮬레이터·실기기 없음 | 📱 항목 | 해당 항목에 "미검증"을 적는다. 순수 로직 테스트로 대체 가능한 것만 대체한다. |
| 학습 의욕 저하 | 2일 이상 시작 의식만 함 | 주간 재계획(5절)을 한다. 강도를 낮추는 것이 맞다. 몰아서 하지 않는다. |

## 3. 60분판 시간표

| 구간 | 분 | 비고 |
|------|----|------|
| 시작 의식 | 5 | `git status`, `nvm use`, "내일 할 일" 확인 |
| 읽기 | 5 | 해당 함수나 분기 한 곳만 |
| 수정 | 30 | 직접 타이핑 |
| 검증 | 5 | `npm run typecheck` · `npm test` · `npx eslint .` |
| 기록 | 15 | `reviews/N-N.md`와 "내일 할 일" 한 줄. 줄이지 않는다 |

재현은 생략하지 않고 다음 날 첫 5분으로 옮긴다. 기록 15분은 줄이지 않는다.

## 4. 자르기 순서

시간이 계속 모자랄 때 아래 순서로 뺀다. 위에 있을수록 나중에 뺀다.

1. 2-5의 `AbortSignal` (금요일 버퍼에서 끝내지 못하면 뺀다)
2. 3-3 ②의 `AuthContext` 분리 (측정에서 이득이 없으면 어차피 되돌린다)
3. 3-4의 CI 워크플로 (로컬에서 `typecheck` · `test` · `lint`가 통과하면 CI는 후속으로 넘긴다)
4. 📱 실기기 확인 항목 (2-6 카메라, 1-4·1-5 cold start). 미검증으로 넘기고, 실기기가 생기면 재검증한다.
5. 2-10의 전역 선언 실험 (`import type` 정리만 하고 나머지는 근거와 함께 기록한다)

**자르지 않는다**: 1단계 복원, 각 미션의 `reviews/N-N.md` 기록, Tier 종료 절(1-6 이후, 2-11 이후, 3-3 이후), 2-3의 변경 전후 기록, 2-11의 테스트 1개 이상.
