# Day 14 — 기록·피드 라우트 분리 검증 결과

**날짜**: 2026-11-24  
**유형**: refactor  
**관련 파일**: `app/index.tsx`, `app/write.tsx` (신규)

## 핵심 (3줄 이내)

- 한 화면이던 기록 폼과 피드를 라우트 두 개로 나눴다. 피드는 `app/index.tsx`(`FeedScreen`), 기록은 `app/write.tsx`(`WriteScreen`)이며, 탭 버튼 대신 `Link`로 이동한다.
- 나누면서 기록 목록 상태가 `write.tsx` 로컬 state가 되었다. 화면을 떠나면 기록이 사라질 수 있어 시뮬레이터에서 확인이 필요하다.
- 타입체크와 `app/`·`src/` 린트는 통과했다. 시뮬레이터 동작 확인은 아직 하지 않았다.

## 알아야 할 것

- **라우트 분리**
  - 무엇: `/`는 피드, `/write`는 기록 화면이다. 상단 `Link`로 서로 이동한다.
  - 왜: Day 14 "만들기" 절의 요구사항이다.
  - 영향: 기존 탭 전환 UI(`tab` state, 탭바)는 제거되었다.
- **피드 목록을 섹션에서 평면 목록으로 변경**
  - 무엇: `SectionList`를 `FlatList`로 바꿨다. 사용자별 섹션 헤더(`User N`)와 sticky 헤더가 없어졌다. `groupByUser`도 삭제되었다.
  - 왜: 피드 화면의 역할을 단순화하라는 계획에 따랐다.
  - 영향: 피드 개수 헤더, 빈 상태 문구, 당겨서 새로고침(`onRefresh`)은 그대로 유지된다.
- **기록 목록 상태 위치**
  - 무엇: `entries` state가 `WriteScreen` 안에 있다.
  - 왜: 기록 폼과 목록이 같은 화면에 있어 그대로 옮겼다.
  - 영향: 피드로 이동한 뒤 기록 화면으로 돌아오면 `entries`가 초기화될 수 있다. 이전 탭 방식에서는 유지되던 동작이라 차이가 생긴다.
- **미사용 export 정리**
  - 무엇: `app/index.tsx`의 `export const styles`를 제거했다. 피드에 쓰는 스타일 3개만 남겼다.
  - 왜: 라우트 파일이 불필요하게 export를 노출하지 않도록 했다.
  - 영향: 없음.
- **`onSubmitEditing` 시그니처**
  - 무엇: 미사용 이벤트 파라미터 `e`와 그 타입 import를 제거했다.
  - 왜: 타입 경고를 없애기 위해서다.
  - 영향: 없음.

## 미확정·확인 필요

- **시뮬레이터 동작 확인 (미실시)**
  - 피드에 `MOCK_POSTS` 카드가 보이는지, `글쓰기`로 기록 화면에 이동하고 헤더 뒤로가기가 되는지, 저장한 기록이 기록 목록에만 나타나고 피드에는 없는지 확인해야 한다.
  - 특히 피드로 갔다 돌아왔을 때 기록 목록이 유지되는지 확인해야 한다. 유지되지 않으면 `entries`를 공유 상태로 올리는 것을 검토한다.
- **`npm run lint` 전체 실패**
  - 실패 원인은 gitignore 대상인 `expo-env.d.ts`의 prettier 오류 1건이다. `app/`·`src/` 린트는 통과했다.
  - 이 파일은 `expo start` 실행으로 생성·갱신되었다. 이번 변경 전에도 같은 오류가 있었는지는 확인하지 않았다.
- **계획에서 제외된 항목 (코드에 없음, 미구현)**
  - `src/data/entries.ts`와 `ENTRIES`는 코드에 없어 이동하지 않았다.
  - Day 12의 `now`, `useNow`도 코드에 없어 이동하지 않았다.
  - 헤더 제목 문자열, 예측 비교, 깨뜨려 보기는 학습자가 직접 수행하는 항목이라 코드 작업에서 제외했다.
