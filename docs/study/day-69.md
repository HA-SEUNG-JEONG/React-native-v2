## 주간 점검 퀴즈(25분)

정답을 가리고 답한 뒤 확인한다. 모르면 "모른다"고 적는다.

1. (Day 65) DevTools의 Sources 탭에서 `debugger;`로 멈춘 뒤 무엇을 확인할 수 있는가? 그리고 Network 탭은 어떤 조건에서만 동작하는가?
2. (Day 66) `ios.simulator: true`로 만든 development build를 실기기에 설치할 수 없는 이유와, 그래서 `eas.json`에서 어떻게 프로필을 구성해야 하는가? Expo Go로는 안 되고 development build가 필요한 경우는?
3. (Day 67) `process.env['EXPO_PUBLIC_API_BASE_URL']`이 `undefined`가 되는 이유와, `EXPO_PUBLIC_` 변수에 비밀 키를 넣으면 안 되는 이유는?
4. (Day 67) 앱 아이콘이나 스플래시를 바꾸면 JS를 고칠 때와 달리 새 빌드가 필요한 이유는? 아이콘 PNG 규격(iOS)은?
5. (Day 68) EAS Update로 배포할 수 있는 변경과 없는 변경을 예로 들고, `runtimeVersion`과 `channel`이 각각 어떤 문제를 막아 주는가?

<details>
<summary>정답</summary>

1. 실행이 멈춘 시점의 Scope에서 변수 값을 보고, Step 버튼으로 한 줄씩 진행하며 호출 스택을 따라갈 수 있다. Network 탭은 Expo 문서 기준으로 `expo-dev-client`가 설치되어 있거나 Expo Go를 쓸 때만 동작한다.
2. 시뮬레이터 빌드는 시뮬레이터용 바이너리라 실기기에 설치할 수 없다. 그래서 시뮬레이터용 프로필(`ios.simulator: true`)과 실기기용 프로필을 따로 둔다. 실기기용 iOS 빌드는 유료 Apple Developer 계정과 기기 UDID 등록이 필요하다. Expo Go에 포함되지 않은 네이티브 코드가 필요할 때, 예를 들어 푸시 토큰(Day 48)처럼 실기기와 development build가 필요한 기능이다.
3. Expo는 빌드 시점에 `process.env.EXPO_PUBLIC_NAME`을 점 표기법으로 정적으로 쓴 참조만 값으로 치환하므로 대괄호 접근이나 구조분해는 치환되지 않아 `undefined`가 된다. `EXPO_PUBLIC_` 값은 앱 번들에 평문으로 들어가 누구나 볼 수 있으므로 비밀 키는 앱에 두면 안 된다.
4. 아이콘·스플래시는 `app.json`의 값이 네이티브 빌드 과정(config plugin)에서 앱 바이너리에 반영되는 설정이라 런타임에 바꿀 수 없고 새 바이너리가 필요하다. iOS 아이콘은 정확히 정사각형인 PNG(권장 1024x1024)여야 하고 둥근 모서리나 투명 픽셀 없이 전체를 채운다.
5. 배포 가능: JS 코드, 스타일, 이미지 같은 비네이티브 요소. 불가능: 네이티브 코드·의존성 변경, 앱 권한 변경, Expo SDK 버전 업데이트. `runtimeVersion`은 업데이트가 호환되는 네이티브 코드를 가진 빌드에만 전달되게 해서 없는 네이티브 모듈을 호출하는 업데이트가 오래된 빌드에 가는 것을 막는다. `channel`은 빌드가 어느 업데이트 브랜치를 받을지 정하므로 `preview` 빌드에 `production` 업데이트가 섞이는 것을 막는다.

</details>

## 구술 1주제(20분)

주제: Daily Log 전체 구조. "처음 보는 개발자에게 Daily Log를 5분 안에 설명한다." 휴대폰으로 녹음하거나 화이트보드를 쓰면서 소리 내어 설명하고, 아래 핵심어가 모두 나왔는지 다시 들으며 체크한다. 각 항목에서 "왜 그렇게 했는가"를 한 문장 이상 말해야 통과다.

핵심어
- 3탭 라우팅 구조 (`expo-router`의 파일 기반 라우팅, Stack·Tabs·보호된 라우트)
- 서버 상태와 클라이언트 상태의 분리 (TanStack Query와 Context·`useReducer`)
- 저장과 인증 (AsyncStorage, SecureStore, 모의 로그인 흐름)
- 네이티브 기능과 권한 (이미지 선택, 위치, 알림)
- 품질과 배포 (테스트, 성능 측정, EAS Build·Update)

설명 체크리스트
- [ ] 피드·기록·설정 3탭 각각이 어떤 파일과 데이터로 구성되는가
- [ ] 피드 목록이 JSONPlaceholder에서 화면까지 오는 길(API 클라이언트 → 쿼리 → `FlatList`)
- [ ] 로그인 상태가 앱 전체에 공유되고 보호된 라우트가 막는 방식
- [ ] 글 작성(기록 탭)에서 사진·위치를 붙일 때 권한을 다루는 순서
- [ ] 다크 모드·접근성·오프라인 처리 중 하나를 골라 구현 이유
- [ ] 테스트로 고정한 것과 고정하지 못한 것
- [ ] 개발 빌드, 앱 변형(`app.config.ts`), OTA 업데이트가 각각 해결하는 문제
