# Day 30 · 11/22 (일) — 미션 3-2 중복 추출 (2/2): 구현 ⚠️

> **오늘의 핵심**: 작은 것부터 하나씩 추출하고 추출마다 검증·커밋을 나눠야, 깨졌을 때 어디서 깨졌는지 찾을 수 있다.

**시작 상태**: [Day 29](./day-29.md)에서 만든 조사표·호출부 표·설계안과 무한스크롤 footer 추출 1개가 출발점이다. 스텁이 건드리지 않은 미션이다. 표시는 ⚠️ 동작 변경 (미세: Android ripple).

## 오늘 할 일 (총 90분)
- [ ] 00~05 시작 의식: `git status --short --branch`, `nvm use 22.21.1`, 어제 "내일 할 일" 확인 (추출마다 `npm run typecheck` · 해당 화면 시뮬레이터 확인 · 커밋 분리)
- [ ] 05~15 추출 ①: 무한스크롤 footer (어제 시작한 것) 마무리 → 확인: 피드 끝까지 스크롤하면 footer 스피너
- [ ] 15~30 추출 ②: `ErrorView` (에러 화면 3곳) → 확인: 어제 정한 `unknown` 메시지 처리대로 세 화면의 문구가 그대로
- [ ] 30~45 추출 ③: `PermissionBlockedNotice` → 확인: 문구·버튼 라벨은 화면마다 그대로
- [ ] 45~60 추출 ④: `ComposeScreen`의 `Pressable` → `Btn` → 확인: `kind="ghost"`가 맞는지, 글자색이 3-1 토큰을 통해 한 곳에서 나오는지
- [ ] 60~75 검증: 아래 참고의 `grep` 두 개와 시뮬레이터 확인 4가지 (피드 에러 화면 · 무한스크롤 footer · 권한 안내 · 모달 `닫기`)
- [ ] 75~90 기록: `docs/improve/reviews/3-2.md` 상단 `⚠️ 동작 변경`, ripple 결정, 각 추출의 props가 왜 그 모양인지, 내일 할 일 한 줄

## 끝 조건
1. `grep -rn "다시 시도" src`는 에러 화면 정의가 한 곳만, `grep -rn "openSettings" src`는 안내 컴포넌트 안에만 남고, 시뮬레이터 확인 4가지가 변경 전과 같다 (Android ripple 제외).
2. 검증 4종이 통과하고, 에러 화면 유도를 위해 잘못된 경로로 바꾼 피드 API URL(`src/api/posts.ts`)을 원복했다.
3. 말로 설명: 추출한 컴포넌트의 props가 왜 그 모양인지, 추출하지 않고 남긴 것이 있다면 이유.

## 막히면
- 여러 추출을 한꺼번에 하다 어디서 깨졌는지 모르겠다면: 마지막으로 통과한 커밋으로 돌아가 하나씩 다시 한다.
- `ErrorView`의 `error`가 `Error`가 아닐 수 있는 경우나 `PermissionBlockedNotice`의 `status` 타입 맞추기에서 15분 막히면 `3-2 힌트 3`(함정)을 요청한다. 정답 코드는 요청하지 않는다.
- 순서 5번(Notification 권한 함수 통합, 호출부 표대로 동작 유지)이 안 끝나면 11/26 예비일([Day 34~35](./day-34.md))로 넘긴다.

## 참고 (아래로 밀어 둠)

**읽을 학습 가이드 절**: 없음. 미션 문서 [3-2](../improve/tier3-cleanup.md)의 힌트와 흔한 함정 절.

**순서 (작은 것부터, 추출마다 검증)**
1. footer (어제 시작)
2. `ErrorView`
3. `PermissionBlockedNotice`
4. `ComposeScreen`의 `Pressable` → `Btn` (`kind="ghost"`가 맞는지, 글자색이 3-1 토큰을 통해 한 곳에서 나오는지)
5. Notification 권한 함수 통합 (호출부 표대로 동작 유지)

추출 하나마다 `npm run typecheck`와 해당 화면 시뮬레이터 확인을 하고 커밋을 나눈다. 5개를 한꺼번에 하면 어디서 깨졌는지 찾기 어렵다. 위 체크박스는 ①~④만 90분에 넣었고, 5번이 안 끝나면 11/26 예비일로 넘긴다.

**검증**

```bash
grep -rn "다시 시도" src        # 에러 화면 정의가 한 곳만
grep -rn "openSettings" src     # 안내 컴포넌트 안에만
```

- 피드 에러 화면: 피드 API URL을 임시로 잘못된 경로로 바꿔 4xx/5xx를 유도(기본 retry 정책 후 표시, **확인 후 원복**). 시뮬레이터에는 비행기 모드가 없고 오프라인이면 에러가 아니라 pause된다.
- 무한스크롤 footer: 피드 끝까지 스크롤.
- 권한 안내: Settings 앱에서 알림/위치 권한을 거부 후 재진입. 📱 카메라 안내는 실기기.
- 모달 `닫기` 버튼 동작·모양이 변경 전과 같은지 (Android ripple 제외).

**완료 기준**: 미션 §6 구현 5개. 추출하지 않고 남긴 것이 있으면 이유를 기록.

**수정 중 확인**: 문구를 "통일"하지 않는다. `Btn`으로 바꿀 때 `disabled` 스타일이나 `kind` 기본값이 바뀌어 보이는 것을 놓치지 않는다.

**임시 코드 되돌릴 곳**: `src/api/posts.ts` (피드 API URL을 잘못된 경로로 바꾼 것).

**기록 포인트**: 상단 `⚠️ 동작 변경`, ripple 결정, 각 추출의 props가 왜 그 모양인지.
