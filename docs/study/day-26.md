## 끝 조건
1. `grep` 두 개를 다시 돌렸을 때 토큰 정의 외에 남은 곳이 없고, 기준선 스크린샷과 화면이 같으며 업로드와 WebSocket이 계속 동작한다.
2. 검증 4종(typecheck · `npm test` · eslint · 같은 재현 절차 재실행)이 통과하고 임시 코드가 남지 않았다.
3. 말로 설명: RN에서 색이 `StyleSheet` 밖(props)에 들어가는 사례와 이유.

## 막히면
- 토큰 정의를 `StyleSheet.create` 위로 올리면 참조는 되는데 별도 파일로 빼면 순환 import가 나는 경우: `Btn.tsx`가 이미 `src/theme/styles.ts`에 의존한다는 점부터 확인하고, 15분 막히면 `3-1 힌트 1`(방향)을 요청한다.
- 정규식 일괄 치환이 `#fff`나 주석까지 건드린 경우: 한 곳씩 되돌려 바꾸고, 그래도 막히면 다음 힌트 단계를 요청한다 (정답 코드는 요청하지 않는다).

## 참고 (아래로 밀어 둠)

**읽을 학습 가이드 절**: 이 미션에서 새 API는 없다. 미션 문서 [3-1](../improve/tier3-cleanup.md)의 공식 문서 절(FlatList의 `refreshControl`)만 확인한다.

**기준선 (코딩 전)**

```bash
grep -rn "#8a92a6\|#93c5fd" src App.tsx            # 줄 수를 기록
grep -rnE "https?://|wss?://" src App.tsx          # URL 위치
```

문서의 숫자(10, 9, URL 5곳)와 현재 숫자를 비교해 어긋나면 기록한다. 시뮬레이터에서 **탭바 활성/비활성 색, 스피너 색, placeholder 색, pull-to-refresh 색을 미리 스크린샷**으로 남겨 둔다. 이 미션은 화면이 달라지면 안 된다.

**코딩 전에 정할 것**
- 토큰 이름 규칙: 기존 `ghostText`는 "쓰임새" 이름이다. 지금 같은 값이 스피너·탭 활성색에도 필요하다. 쓰임새 기준을 이어갈지 의미 기준으로 바꿀지 한 줄 규칙으로 정한다.
- URL: 환경별로 바뀌는 값인가, 단순히 한곳에 모으면 되는 값인가. `FeedListScreen`의 썸네일은 id가 들어가는 템플릿이다.
- 값이 같아도 의미가 다른 색(`#2b3446` 등)은 합치지 않는다. 필수 범위는 위 두 색이다.

**수정 중 확인**
- 토큰 정의가 `StyleSheet.create` 위에 있어야 참조할 수 있다.
- 토큰을 별도 파일로 빼면 순환 import가 생길 수 있다 (`Btn.tsx`가 이미 `styles.ts`에 의존).
- 정규식 일괄 치환은 `#fff`나 주석까지 건드린다. 한 곳씩 바꾸고 `tsc`를 자주 돌린다.

**임시 코드 되돌릴 곳**: 없음.

**기록 포인트**: 사용처 표(style 안 / props 안), 토큰 이름 규칙 한 줄, 기준선 숫자와 문서 숫자의 차이.
