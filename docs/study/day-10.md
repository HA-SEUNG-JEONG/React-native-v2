# Day 10 · 11/2 (월) — 미션 1-5 로그아웃 상태 알림 딥링크 유실 (⚠️ 동작 변경 · 📱 cold start는 실기기)

> **오늘의 핵심**: "링크 열기"와 "링크 보관"은 다른 일이다. 로그아웃 상태에서는 대상 네비게이터가 마운트돼 있지 않아 링크가 유실되므로, 동작 변경의 부작용을 정책으로 먼저 글에 쓴 뒤 구현한다.

**시작 상태**: [Day 8~9](./day-08.md)에서 복원한 알림 훅(`App.tsx`의 알림 탭 처리 `useEffect`)이 출발점이다. 그 훅의 의존성이 `[isReady, lastResponse]`뿐이었다면 아래 재현 3번(로그인해도 홈)이 그대로 나온다. 이미 로그아웃 상태까지 고려해 썼다면 "변경 전"에 "Day 8~9에서 대응함"이라고 적고, 그 대응이 아래 재현을 통과하는지만 검증한다. 1-4 구현이 남았다면 먼저 금요일 버퍼에서 끝낸다. 오늘은 **정책을 먼저 쓰는 것**이 구현보다 중요하다. 규칙: [rules.md](./rules.md)

## 끝 조건
1. 시뮬레이터에서 재현 절차 → 로그인 → `FeedDetail` 이동. 이어서 로그아웃 → 로그인을 반복했을 때 **같은 화면으로 다시 가지 않는다.** 비회귀: 로그인 상태에서 알림 탭 → 즉시 `FeedDetail`.
2. 검증 4종 통과 + 미션 §6 체크 + 정책 표 전부 채움 + 변경 전후 표 작성. 📱 cold start(로그아웃 → 앱 완전 종료 → 알림 탭 → 로그인)는 실기기가 없거나 Expo Go 시뮬레이터가 이 경로를 못 타면 **"미검증"이라고 기록한다. "됐다"고 쓰지 않는다.**
3. 말로 설명: 로그아웃 상태에서 링크가 유실되는 경로(대상 네비게이터 미마운트)는? 로그인 후 재적용하면 사용자 눈에 무엇이 달라지나?

## 막히면
- 정책 표 칸이 안 채워지면(보관 수명, 영속 여부 등) 구현으로 넘어가지 않는다. 사용자 시점에서 "그 링크가 언제까지 유효해야 자연스러운가"를 한 줄 쓰고, 그래도 15분이면 `1-5 힌트 1`(방향)을 요청한다.
- effect 의존성이 막히면 `user`만 추가했을 때 로그인할 때마다 같은 링크가 다시 열리는 문제부터 확인한다 (`1-5 힌트 2`, API 이름).
- 타이밍 문제(`user`가 바뀐 직후 네비게이터 교체 전에 `openURL`)는 `1-5 힌트 3`(함정)을 요청한다. 힌트 3까지 갔는데도 20분 막히면 그날은 멈추고 11/6 버퍼([Day 14](./day-14.md))로 넘긴다.

  - 보관하는 링크는 1-4 검증을 통과한 값이다.
