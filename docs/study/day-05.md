# Day 5 · 10/28 (수) — 미션 1-2 삭제가 무시되면 SwipeableRow가 화면 밖에 남음 · 1/2일차: 복원 · 가설 · 재현
> **오늘의 핵심**: shared value는 리렌더로 돌아오지 않고, 워클릿은 React 상태를 직접 읽으면 오래된 값을 본다. 그래서 삭제가 무시돼도 행의 위치는 누군가 책임지고 되돌려야 한다.

**시작 상태**: `src/components/SwipeableRow.tsx`의 pan `onEnd`가 비어 있어 지금은 스와이프해도 행이 삭제도 원위치 복귀도 하지 않는다 (임계값·애니메이션 import도 지웠다). `useDeletePost`는 `FeedListScreen.tsx`에 연결돼 있지 않으며 두 삭제 핸들러(행, 시트)도 비어 있다. 순서는 ① 복원(임계값 → 화면 밖 + `onDelete` / 원위치, 핸들러에서 `mutate` + 진행 중 가드) → ② 가드가 무시될 때의 증상 재현 → ③ 미션 본론이다. 흐름 B(데이터와 오프라인)의 입구이기도 하다. 규칙: [rules.md](./rules.md)

**한계**: `useDeletePost`가 아직 캐시를 건드리지 않는다(2-3은 [Day 13·15](./day-13.md)). 그래서 삭제가 성공해도 목록에서 행이 사라지지 않고 화면 밖(`-400`)에 안 보이게 남는다. 오늘은 "`onDelete`가 불리는가", "가드로 무시될 때 행이 원위치로 오는가"까지만 판정한다. "성공하면 사라진다"와 롤백은 Day 13·15 이후에 재확인한다.
